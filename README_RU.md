## Назначение

**Template App TRASSIR Windows HTTP SDK** — шаблон Zabbix для мониторинга серверов TRASSIR, работающих под управлением Windows, через встроенный HTTP SDK. Внешние скрипты, SNMP и Zabbix Agent на контролируемом сервере не требуются.

Шаблон контролирует состояние TRASSIR, локальные камеры, глубину архива, архивные диски, запись, параметры потоков и системные статусы. В комплект входят правила LLD, триггеры, прототипы графиков, вычисляемые показатели архива и готовый дашборд.

Этот репозиторий предназначен только для TRASSIR Server на Windows. Для аппаратных регистраторов TRASSIR используется отдельный шаблон, поскольку значения health и набор системных параметров отличаются.

## Основные возможности

- Мониторинг через встроенный HTTP SDK TRASSIR.
- Не требуются внешние скрипты и Zabbix Agent.
- Работа через Zabbix Server или Zabbix Proxy.
- Автоматическое обнаружение локальных камер.
- Автоматическое обнаружение архивных дисков.
- Прямой online/offline-статус камеры по флагу сигнала TRASSIR.
- Покамерный мониторинг FPS, битрейта, записи, архива и диагностических ошибок.
- Контроль глубины архива относительно скользящего среднего за 7 дней.
- Понятные имена камер в названиях и тегах.
- Исключение неархивных дисков из тревог списком через запятую.
- Встроенный дашборд.

## Совместимость

| Компонент | Поддержка |
|---|---|
| Zabbix | 7.2 и новее |
| TRASSIR Server на Windows | Поддерживается |
| HTTP SDK по HTTPS | Поддерживается |
| HTTP SDK по HTTP | Поддерживается |
| Мониторинг через Zabbix Proxy | Поддерживается |
| Локальные каналы TRASSIR | Поддерживаются |
| Удалённые каналы NetworkNode | Исключаются из локального LLD |
| Аппаратные TRASSIR NVR | Этим шаблоном не поддерживаются |

Набор полей HTTP SDK может различаться между версиями TRASSIR. Отсутствующие необязательные поля остаются пустыми или отображаются как `Not supported`, не останавливая основной опрос.

## Собираемые данные

### Сервер

- Доступность HTTP SDK.
- Загрузка процессора.
- Время работы.
- Состояние базы данных.
- Состояние сети.
- Состояние автоматизации.
- Общее состояние дисковой подсистемы.
- Ошибки агрегированного опроса.
- Общее, доступное и недоступное количество локальных камер.
- Процент доступности камер.
- Общая глубина основного, приватного и дополнительного архива.
- Полное количество дней основного архива.
- Скользящее среднее глубины архива за 7 дней.
- Текущая глубина архива относительно среднего за 7 дней.

Все отображаемые системные состояния приведены к единому формату:

```text
-1 = No data
 0 = Error
 1 = OK
```

Специфическое для Windows значение состояния сети нормализуется на preprocessing, поэтому сеть, база данных, автоматизация и диски используют одинаковую логику.

### Камеры

Для каждого локального канала LLD создаёт элементы данных:

- Online/offline.
- Наличие видеосигнала.
- FPS основного потока.
- FPS дополнительного потока.
- Битрейт основного потока.
- Битрейт дополнительного потока.
- Битрейт записи.
- Локальная запись.
- Аппаратная запись.
- Задолженность записи.
- Последняя ошибка записи.
- Ошибка grabber.
- Признак превышения битрейта.
- Признак медленного объединения архива.
- Глубина основного архива.
- Глубина дополнительного архива.
- Расход архива за сутки.
- Прогноз расхода архива.

GUID камеры используется как стабильный технический идентификатор. Имя камеры используется в видимых названиях элементов, триггеров, графиков и тегах.

Триггер недоступности камеры имеет важность `DISASTER`. Триггер потери видеосигнала зависит от Offline, поэтому одинаковые проблемы не дублируются.

### Архивные диски

- Идентификатор диска.
- Модель и серийный номер.
- Ёмкость.
- Глубина архива.
- Состояние включения.
- Режим только для чтения.
- Недоступность.
- Непригодность.
- Необходимость форматирования.
- Текущая скорость.
- Скорость чтения.
- Скорость записи.
- Счётчик ошибок.
- Последняя ошибка SDK.

## Авторизация

SDK-пароль задаётся в макросе узла:

```text
{$TRASSIR.SDK.PASSWORD}
```

SDK-пароль настраивается в параметрах WebServer TRASSIR и может отличаться от пароля оператора.

В качестве адреса HTTP SDK используется адрес интерфейса узла. Интерфейс Agent может использоваться только как носитель IP или DNS; агент на сервер TRASSIR не устанавливается.

## Требования

- Zabbix 7.2 или новее.
- TRASSIR Server на Windows.
- Включённый HTTP SDK.
- Разрешение на чтение настроек SDK.
- Разрешение на чтение дерева объектов SDK.
- Сетевая доступность порта SDK с Zabbix Server или назначенного Proxy.
- Корректный SDK-пароль.

## Установка

1. Скачайте XML из последнего GitHub Release.
2. В Zabbix откройте **Сбор данных → Шаблоны → Импорт**.
3. Импортируйте XML.
4. Создайте узел для Windows-сервера TRASSIR.
5. Добавьте интерфейс Agent с IP-адресом или DNS-именем сервера. Интерфейс используется только как адрес назначения HTTP SDK.
6. Привяжите `Template App TRASSIR Windows HTTP SDK`.
7. Задайте макросы узла.
8. Дождитесь выполнения мастер-элементов и правил LLD.

Подробно: [Установка](docs/INSTALL_RU.md) и [Настройка](docs/CONFIGURATION_RU.md).

## Макросы

| Макрос | По умолчанию | Назначение |
|---|---:|---|
| `{$TRASSIR.SCHEME}` | `https` | Схема HTTP SDK. |
| `{$TRASSIR.PORT}` | `8080` | Порт HTTP SDK. Переопределяется на узле. |
| `{$TRASSIR.SDK.PASSWORD}` | пусто | Обязательный SDK-пароль. |
| `{$TRASSIR.POLL.INTERVAL}` | `2m` | Интервал опроса health и дерева объектов. |
| `{$TRASSIR.CHANNEL.POLL.INTERVAL}` | `5m` | Интервал опроса каждой камеры. |
| `{$TRASSIR.DISK.POLL.INTERVAL}` | `5m` | Интервал опроса архивных дисков. |
| `{$TRASSIR.CPU.WARN}` | `85` | Порог загрузки CPU, %. |
| `{$TRASSIR.RECORD.DEBT.WARN}` | `5` | Порог задолженности записи, секунд. |
| `{$TRASSIR.ARCHIVE.MIN.DAYS}` | `7` | Минимальная общая глубина основного архива. |
| `{$TRASSIR.CHANNEL.ARCHIVE.MIN.DAYS}` | `7` | Минимальная глубина архива камеры. |
| `{$TRASSIR.DISK.EXCLUDE}` | пусто | ID дисков без тревог, через запятую. |

## Исключение дисков

Диски, которые не используются для записи архива, можно исключить из проблем триггеров:

```text
{$TRASSIR.DISK.EXCLUDE}=C,D,R
```

Пробелы и регистр игнорируются. Сбор данных и графики для исключённых дисков сохраняются.

После изменения макроса выполните правило обнаружения архивных дисков или дождитесь следующего цикла LLD.

## Основные триггеры

- Высокая загрузка CPU.
- Ошибка состояния базы данных.
- Общая ошибка дисковой подсистемы.
- Ошибка состояния сети.
- Ошибка автоматизации.
- Нет агрегированных данных от SDK.
- Ошибки агрегированного опроса.
- Одна или несколько локальных камер недоступны.
- Обнаруженная камера офлайн.
- Потеря видеосигнала камеры.
- Задержка или ошибка записи.
- Превышение допустимого битрейта.
- Медленное объединение архива.
- Общая глубина архива ниже порога.
- Глубина архива камеры ниже порога.
- Глубина архива ниже 90% или 80% от среднего за 7 дней.
- Архивный диск отключён, недоступен, непригоден, переведён в read-only или требует форматирования.
- Появились новые ошибки архивного диска.

## Базовая линия архива

Глубина архива зависит от ёмкости дисков, количества камер, битрейта, режима записи и активности сцены. Поэтому дашборд сравнивает текущую глубину основного архива со скользящим средним за 7 дней.

Шаблон рассчитывает:

- Текущую глубину основного архива.
- Полное количество дней архива.
- Скользящее среднее за 7 дней.
- Процент текущей глубины относительно среднего.

Интерпретация дашборда:

```text
90–100%   Норма
80–89,99% Предупреждение
Ниже 80%  Критическое снижение
```

Для репрезентативной базовой линии необходимо накопить достаточную историю.

## Дашборд

Встроенный дашборд отображает:

- Состояние сервера и подсистем.
- Количество доступных и общее количество камер.
- Радиальный индикатор доступности камер.
- Загрузку CPU.
- Текущую глубину архива и полные дни.
- Среднее архива за 7 дней.
- Глубину архива относительно базовой линии.
- Активные проблемы.
- Графики архива, камер и дисков.

Дашборд доступен в контексте узла или шаблона. Он не создаётся как глобальная панель в разделе **Мониторинг → Панели**.

См. [Описание дашборда](docs/DASHBOARD_RU.md).

## Диагностика

- Проверьте последнее значение `System: RAW - health and local channels`.
- Проверьте `System: RAW - aggregate polling errors`.
- Проверьте обнаруженные элементы `Camera: ...: RAW`.
- Проверьте `{$TRASSIR.SCHEME}`, `{$TRASSIR.PORT}` и `{$TRASSIR.SDK.PASSWORD}`.
- Проверьте, что узел контролируется правильным Zabbix Proxy.
- После изменения `{$TRASSIR.DISK.EXCLUDE}` выполните LLD архивных дисков.
- При `sessionbomb protection` удалите дублирующий опрос или увеличьте интервалы.

См. [FAQ](docs/FAQ_RU.md).

## Ограничения

- Шаблон не предназначен для аппаратных регистраторов TRASSIR.
- Обнаруживаются только локальные каналы.
- Аппаратная запись поддерживается не всеми камерами и способами подключения.
- Использование оперативной памяти не включено, поскольку показатель не был стабильно доступен в протестированных Windows HTTP SDK.
- Базовая линия архива становится показательной только после накопления истории.
- Самоподписанные HTTPS-сертификаты встречаются часто; обработка TLS зависит от Zabbix Server или Proxy.
