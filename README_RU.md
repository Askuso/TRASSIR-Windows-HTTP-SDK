# Template App TRASSIR Windows HTTP SDK

## Документация

- [Русская техническая документация](docs/TRASSIR_Windows_HTTP_SDK_Документация.docx)
- [English README](README.md)

## Назначение

Template App TRASSIR Windows HTTP SDK предназначен для мониторинга серверов TRASSIR, работающих под управлением Windows, средствами Zabbix через встроенный HTTP SDK.

Zabbix Agent, SNMP и внешние скрипты не требуются. Запросы выполняются Zabbix Server или Zabbix Proxy встроенными элементами типа SCRIPT.

Шаблон разработан отдельно от версии для аппаратных регистраторов, поскольку Windows Server и NVR возвращают отличающиеся health-значения и имеют разный набор системных параметров.

# Возможности

Шаблон позволяет контролировать:

## Состояние сервера

- Доступность HTTP SDK
- Загрузку процессора
- Время непрерывной работы
- Состояние базы данных
- Состояние автоматизации
- Состояние сети
- Сводное состояние дисков
- Ошибки агрегированного опроса

Все отображаемые системные состояния приведены к единому формату:

- `1` — OK
- `0` — Error
- `-1` — No data

## Камеры

Автоматически обнаруживаются только локальные камеры текущего сервера TRASSIR. Удалённые каналы NetworkNode не включаются.

Для каждой камеры создаются элементы данных:

- Online status
- Video signal
- FPS основного и дополнительного потока
- Битрейт основного, дополнительного и записываемого потока
- Локальная и аппаратная запись
- Задолженность записи
- Последняя ошибка записи
- Ошибка захвата
- Превышение битрейта
- Медленное объединение архива
- Глубина основного и дополнительного архива
- Расход архива за сутки
- Прогноз расхода архива

Статус камеры определяется напрямую по флагу сигнала, который возвращает TRASSIR.

Offline камеры имеет важность `DISASTER`. Триггер потери видеосигнала зависит от Offline, поэтому одинаковые проблемы не дублируются.

## Архив

Получаются:

- Общая глубина основного архива
- Общая глубина приватного архива
- Общая глубина дополнительного архива
- Полное количество дней основного архива
- Средняя глубина основного архива за последние 7 дней
- Процент текущей глубины относительно среднего за 7 дней
- Глубина архива каждой камеры
- Фактический и прогнозируемый расход архива каждой камеры

Радиальный датчик архива использует автоматически вычисляемую базовую линию:

- 90–100% — норма
- 80–89,99% — предупреждение
- ниже 80% — критическое снижение

## Архивные диски

Автоматически обнаруживаются архивные диски.

Для каждого диска получаются:

- Идентификатор
- Модель
- Серийный номер
- Ёмкость
- Глубина архива
- Состояние включения
- Недоступность
- Непригодность
- Режим только для чтения
- Необходимость форматирования
- Текущая скорость
- Скорость чтения
- Скорость записи
- Счётчик ошибок
- Последняя ошибка

Диски, которые не используются для записи архива, можно исключить из тревог:

`{$TRASSIR.DISK.EXCLUDE}=C,D,R`

При этом сбор данных и графики сохраняются.

# Требования

- Zabbix 7.2+
- TRASSIR Server на Windows
- Включённый HTTP SDK
- SDK-пароль с правами чтения
- Сетевой доступ от Zabbix Server или Proxy к порту SDK
- IP или DNS сервера TRASSIR в интерфейсе узла Zabbix

---

# Настройка TRASSIR

Необходимо:

1. Открыть настройки WebServer/SDK.
2. Включить HTTP/Web SDK.
3. Создать или выбрать техническую учётную запись мониторинга.
4. Разрешить чтение настроек и дерева объектов.
5. Записать порт HTTP SDK и SDK-пароль.
6. Проверить доступность порта с Zabbix Server или Proxy.

---

# Импорт шаблона

1. Импортируйте `templates/7.2/template_app_trassir_windows_http_sdk.xml`.
2. Создайте узел для Windows-сервера TRASSIR.
3. Укажите IP-адрес или DNS сервера в интерфейсе узла.
4. Привяжите `Template App TRASSIR Windows HTTP SDK`.
5. Укажите макросы узла.
6. Дождитесь выполнения мастер-элементов и LLD.

---

# Макросы

| Макрос | По умолчанию | Назначение |
|---|---:|---|
| `{$TRASSIR.SCHEME}` | `https` | Схема HTTP SDK |
| `{$TRASSIR.PORT}` | `8080` | Порт HTTP SDK |
| `{$TRASSIR.SDK.PASSWORD}` | пусто | SDK-пароль |
| `{$TRASSIR.POLL.INTERVAL}` | `2m` | Опрос health и дерева объектов |
| `{$TRASSIR.CHANNEL.POLL.INTERVAL}` | `5m` | Отдельный опрос каждой камеры |
| `{$TRASSIR.DISK.POLL.INTERVAL}` | `5m` | Опрос архивных дисков |
| `{$TRASSIR.CPU.WARN}` | `85` | Порог CPU, % |
| `{$TRASSIR.RECORD.DEBT.WARN}` | `5` | Порог задолженности записи, секунд |
| `{$TRASSIR.ARCHIVE.MIN.DAYS}` | `7` | Минимальная общая глубина архива |
| `{$TRASSIR.CHANNEL.ARCHIVE.MIN.DAYS}` | `7` | Минимальная глубина архива камеры |
| `{$TRASSIR.DISK.EXCLUDE}` | пусто | Диски без тревог, через запятую |

# Дашборд

Шаблон содержит готовый дашборд.

На дашборде отображаются:

- состояние сервера и подсистем;
- загрузка CPU;
- доступность камер;
- количество доступных камер из общего количества;
- общая глубина архива;
- полные дни архива;
- среднее за 7 дней;
- глубина архива относительно среднего;
- активные проблемы;
- графики камер, архива и дисков.

Дашборд открывается в контексте узла или шаблона. Он не создаётся в глобальном разделе `Мониторинг -> Панели`.

# Известные особенности

- Шаблон предназначен только для TRASSIR Server на Windows.
- Аппаратные регистраторы используют отдельный шаблон.
- Обнаруживаются только локальные камеры.
- Аппаратная запись поддерживается не всеми камерами; в таком случае выводится `Not supported`.
- Использование RAM не включено, поскольку показатель не был стабильно доступен в протестированном Windows SDK.
- Для стабильного среднего архива требуется накопление истории.
- Серый индикатор ZBX не означает недоступность TRASSIR: шаблон не использует Zabbix Agent.

# Диагностика

- Проверьте `System: RAW - health and local channels`.
- Проверьте `System: RAW - aggregate polling errors`.
- Проверьте RAW-элементы обнаруженных камер.
- Проверьте схему, порт и SDK-пароль.
- Проверьте назначенный Zabbix Proxy.
- После изменения списка исключённых дисков выполните LLD дисков вручную.
- При `sessionbomb protection` удалите дублирующие шаблоны или увеличьте интервалы опроса.
